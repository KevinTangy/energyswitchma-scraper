# Electricity Rate Tracker

Daily scraper that tracks retail electricity supply offers from
[EnergySwitch MA](https://energyswitchma.gov) (the state's official
comparison site) for 19 cities and towns in and around Boston. It records every supplier's
¢/kWh rate, then builds a README comparing each city's utility basic service
(National Grid or Eversource) against the cheapest offer.

Owner: Kevin. Runs on GitHub Actions; this local repo is a clone of that
GitHub repo.

## Repo layout

```
scrape.py                     # Scrape one ZIP -> append rows to data/rates.csv
probe.py                      # Check which utility page (1 or 2) each ZIP uses
cities.csv                    # Cities the daily job scrapes: zip,city,compare_id
candidates.csv                # ZIPs being considered (input for probe.py)
make_charts.py                # data/rates.csv -> charts/*.svg + README.md
.github/workflows/scrape.yml  # Daily job: scrape cities.csv, build charts, commit
.github/workflows/check-utilities.yml  # Manual: run probe.py on GitHub
data/rates.csv                # The running dataset (all cities, all days)
data/raw/<zip>/<date>.json.gz # Raw JSON captured from the site each day (gzip)
data/raw/<zip>/<date>.txt.gz  # Page text, for debugging when JSON is missing
charts/savings.svg            # Today's savings bar chart (README); -dark.svg variant
charts/all-cities.svg         # Grid of small charts, one per city (README); -dark.svg
charts/<city>.svg             # Larger single-city chart, linked from README; -dark.svg
README.md                     # GENERATED by make_charts.py. Never edit by hand
docs/                         # Background docs (see below)
```

## Commands

```bash
pip install playwright matplotlib
python -m playwright install chromium

python scrape.py 02148 --city Malden          # live scrape (headless Chromium)
python scrape.py 02138 --city Cambridge --compare-id 2     # Eversource page
python scrape.py 02138 --city Cambridge --compare-id auto  # try both pages
python probe.py 02148 02138                    # which page has offers? (changes nothing)
python make_charts.py                          # rebuild charts + README

# Re-process a saved capture without hitting the site:
python scrape.py 02148 --city Malden --from-raw data/raw/02148/2026-11-18.json.gz --date 2026-11-18
```

`scrape.py` writes to `data/rates.csv` in the current directory. Re-running a
ZIP for a date it already has REPLACES that ZIP's rows for that date (no
duplicates); other days and ZIPs are kept. Dates default to today in
America/New_York, not UTC. When testing with `--from-raw`, still run it from
a scratch directory (or back up the CSV) so you don't overwrite real data.

To add or remove a city, edit `cities.csv` (`zip,city,compare_id`; no commas
in city names). `compare_id` is the utility's page: `1` = National Grid,
`2` = Eversource. Find it with `probe.py` or the "Check which utility page
each ZIP uses" workflow before adding a city.

Not candidates: towns served by a municipal light plant (Wakefield,
Reading, Belmont, Peabody, Lynnfield, etc.). By law (M.G.L. c. 164 §47A)
their residents can't buy from competing suppliers, so EnergySwitch has no
offers for them.

## How scraping works

- The site is a JavaScript single-page app. Plain HTTP fetches return an empty
  shell, so `scrape.py` loads the page in headless Chromium (Playwright) and
  captures the JSON responses.
- Page URL: `https://energyswitchma.gov/#/compare/{compare_id}/1/{zip}//`,
  one page per utility: `1` = National Grid, `2` = Eversource. Each city
  uses only the page for the utility that serves it. `choose_compare_id()`
  in `scrape.py` decides: a page counts only if it lists REGULAR supplier
  offers. A town's own electricity program (municipal aggregation) shows up
  on both pages, so it doesn't count. The site names a utility on every page
  (page 1 always says National Grid), so the name alone proves nothing.
- Site quirks seen in the Nov 18 check of 68 ZIPs: each utility page has
  ~37 regular offers; towns with a program add 2-3; a few ZIPs that straddle
  both utilities (Everett 02149, Medford 02155, Quincy 02169) show regular
  offers on both pages and need a manual choice; and the site lists
  Eversource offers for Wakefield and Belmont even though they're municipal
  light plant towns. Treat the site's results as a hint, not proof.
- The offer list comes from the JSON response at
  `https://energyswitchma.gov/consumers/compare`: a list with one object per
  offer. See `docs/data-source.md` for the fields.
- `scrape.py` exits with code 1 if no offers are found. The workflow keeps
  going through the remaining cities and fails at the end, so GitHub sends an
  email.

## data/rates.csv: required format (Kevin's requirements)

Columns, in order: `date, zip, city, supplier, price_cents_per_kwh, term, fees`

- **supplier** is the supplier NAME (`supplierName`), never the numeric ID.
  An early version wrongly used `supplierId`.
- **Basic service is split into two rows**, one per price period. The
  source puts both in one record, joined by `|`, in both `pricePerUnit` and
  `contractTerm`. These rows are labeled `<utility> (Basic Service)` using
  the site's name: `National Grid (Basic Service)` or
  `NSTAR d/b/a Eversource Energy (Basic Service)`.
- **price_cents_per_kwh** is a bare number (`17.185`), not `17.185 ¢/kWh`.
- **fees**: cancellation fee text (or `No cancellation fee`), plus the
  enrollment fee and monthly charge when they exist.
- **Removed by request:** product, renewable and price_type columns.
- **Sort order within each date+city batch:** the two basic service rows
  first (earlier period first), then all other offers from cheapest to most
  expensive. Ties are broken by supplier name.
- **One batch per date+ZIP.** A second run on the same day replaces that
  day's rows for the ZIP. The file is kept in date order.
- If the header of an existing CSV doesn't match these columns, `scrape.py`
  renames the old file to `data/rates_old_format.csv` and starts a new one.

## README and charts (make_charts.py)

The README shows two images, and both scale as cities are added:

- **Savings bar chart** (`draw_savings`): one horizontal bar per city for
  today's savings (basic service minus cheapest offer), biggest first, with
  the value and cheapest supplier at the bar end. Gray bars mean basic
  service is cheaper.
- **Grid of small charts** (`draw_grid`): one panel per city with the two
  lines described below. All panels share the same ¢ and date scale, so
  cities can be compared at a glance. Cities are ordered by today's savings,
  the same order as the bar chart. 2 columns up to 4 cities, 3 up to 12,
  then 4.

The larger per-city charts (`draw`) are still generated and linked from the
README. Each has:

- Two series:
  1. **Utility basic service** (National Grid or Eversource, named from the
     `(Basic Service)` rows): the rate for whichever period covers
     that day, found by parsing terms like `Aug '26 through Jan '27`. Drawn
     as a step line.
  2. **Cheapest offer:** the lowest-priced row that isn't basic service,
     labeled with the supplier name when the cheapest supplier changes. Runs
     of a day or two and labels too close together are skipped; the latest
     supplier is always labeled.
- The charts are rebuilt from every date in `data/rates.csv` on each run, so
  history builds up one point per day. Don't trim old rows from the CSV.
- The latest value is printed at the right end of each line.
- Light and dark SVGs, shown through `<picture>` with
  `prefers-color-scheme`. Colors come from a colorblind-safe palette that
  was checked with a palette-checking tool: blue `#2a78d6` / `#3987e5` for
  basic service, orange `#eb6834` / `#d95926` for the cheapest offer.
- The README also has a "Today's savings" table with utility, basic, cheapest,
  supplier and savings (basic minus cheapest, positive = cheaper than basic),
  in ¢ to 3 decimals, sorted by savings.
- If `data/rates.csv` doesn't exist, the script exits cleanly so the commit
  step still runs.

## GitHub Actions

- Schedule: `cron: "11 6 * * *"` with `timezone: "America/New_York"`, so
  6:11 AM Eastern all year (daylight saving included), plus a backup run at
  12:41 PM Eastern (`41 12 * * *`) in case the morning run is dropped. The
  backup replaces the day's rows, so it never duplicates. `concurrency`
  makes overlapping runs wait for each other, and the commit step does
  `git pull --rebase` before pushing. Without `timezone`,
  GitHub reads cron as UTC. GitHub's docs warn scheduled runs can be delayed
  or dropped under load; Nov 18's ran 8 hours late and Nov 19's didn't run
  by 10 AM. Also has `workflow_dispatch` for manual runs.
- Steps: install Playwright and matplotlib, then scrape each city in
  `cities.csv` in a loop, passing its `compare_id`
  (with a 15-second pause between cities, `PAUSE_SECONDS`, to go easy on the
  site), then `make_charts.py`, then commit `data charts README.md` as `rate-bot`,
  then fail the run if any city returned no offers.
- Needs `permissions: contents: write` (already set).

## Conventions

- Keep `scrape.py` usable on its own for a single ZIP. The workflow loops
  over cities.
- Keep the raw JSON capture every day. It lets you reprocess history with
  `--from-raw` when the parsing changes. Captures are saved as compact,
  gzip-compressed JSON (about 7 KB instead of 112 KB), so the repo stays
  small as cities are added. Read one with `zcat file.json.gz`.
  `--from-raw` also still accepts older uncompressed `.json` files.
- Don't hand-edit `README.md`; change `write_readme()` in `make_charts.py`.
- Test parsing changes against `data/raw/02148/2026-11-18.json.gz` before
  pushing.
